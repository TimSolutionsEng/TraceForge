# Day 6 — Security Alert Persistence

## Overview

Today, I extended TraceForge by implementing persistent storage for security alerts. Previously, my detection engine could identify suspicious login activity, but the generated alerts were only stored temporarily in memory.

I implemented an alerts table in SQLite and integrated alert storage into the application's processing pipeline.

## Work Completed

### 1. Created the Alerts Database Table

I updated `database/database.py` to create a separate `alerts` table alongside the existing `events` table.

The alerts table stores:

- Alert ID
- Alert key
- Alert type
- Source IP address
- Number of failed attempts
- Severity
- Description

### 2. Implemented Alert Storage

I created the `save_alerts()` function.

This function:

- Accepts alerts generated by the detection engine.
- Generates a SHA-256 hash to identify each alert.
- Inserts alerts into the SQLite database.
- Uses `INSERT OR IGNORE` to prevent duplicate records.
- Returns the number of newly inserted alerts.

### 3. Integrated Alert Storage into the Application

I updated `backend/app.py` to call `save_alerts()` after detecting suspicious activity.

The application now reports:

- Total logs collected
- Events parsed
- Events saved
- Alerts saved
- Alerts detected

### 4. Improved Automated Testing

I extended `test_database.py` to test alert table creation, insertion, duplicate prevention and retrieval.

I also updated `test_app.py` to verify that alerts are detected, saved in the database and not inserted again when the same logs are processed.

## Testing Results

The complete automated test suite was executed using:

`python3 -m pytest -v`

**Result: 28 tests passed.**

The application was also executed successfully using:

`python3 -m backend.app`

The application collected and parsed four log entries. No new events or alerts were inserted because the events had already been stored and the sample logs did not meet the brute-force detection threshold.

## What I Learned

- The difference between security events and detection alerts.
- How to persist detection results using SQLite.
- How SHA-256 hashing can help identify duplicate records.
- How `INSERT OR IGNORE` prevents duplicate database entries.
- How to test database persistence independently and through an end-to-end application test.
- Why detection and persistence are separate operations.

## Current Project Status

TraceForge can now collect logs, parse authentication events, detect repeated failed login attempts, store events and persist generated security alerts.
